# Megara 2.0.0 evidence archive input contract

## Immutable-tag recovery path

If the original tag-push workflow cannot preserve an annotated tag object on
its runner, recovery must use workflow_dispatch from the fixed default branch.
The required inputs are `release_tag`, `release_commit`, `release_tag_object`,
and `main_at_release`. The workflow explicitly fetches
refs/tags/<release_tag>, verifies the remote and local tag object and peeled
target, then checks out and builds only the peeled release commit. A recovery
target must equal main_at_release and be an ancestor of current main; it must
not move, recreate, or replace the immutable tag.

The archive is generated by the same release workflow from either a tag push
or a validated immutable-tag recovery dispatch. The workflow is
`.github/workflows/release.yml`, and the local `target/megara-evidence`
directory is staging only and is never treated as the final archive.

## Required binding

The final archive must be generated from the exact clean commit targeted by
`v2.0.0` and must contain the `megara.release-evidence/v1` manifest, the raw
command stdout/stderr, `test-report.txt`, DB/FS/protocol/migration/purge
traces, command exit codes, and SHA-256 hashes for every file except the
manifest itself. The workflow upload name is:

```text
megara-planning-release-evidence-<release-commit>
```

The retention period is 90 days and `if-no-files-found: error` is required.
Source or `Cargo.lock` changes after evidence generation invalidate the bundle.

documents are integrated. The final RDR must record the plain-text v2.0.0
approval, annotated tag object type, exact main target, tag workflow URL,
artifact URL, artifact hash/manifest, and release asset checksums.
Cryptographic tag/RDR signatures are explicitly not required for v2.0.0 only;
this does not permit a lightweight or moved tag.
